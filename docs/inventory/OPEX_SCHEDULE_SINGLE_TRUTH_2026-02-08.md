# OPEX Schedule Single Truth (2026-02-08)

Purpose: keep OPEX commitments reproducible from one canonical source workbook and keep DB/event views synchronized.

## Source Workbook

- Path: `~/Documents/useful tables/Main crm spreadsheets/main tables/Protocols/OPEX_protocol_26.01.2026.xlsx`
- Parser contract: `scripts/import_opex_protocol.py` (`Sheet1` columns must include schedule, amount, and anchor date fields).

## Canonical Repo Artifacts

- `config/opex/opex_schedule.yaml`
  - metadata (`source_xlsx`, generation timestamp, horizon, row count)
- `config/opex/opex_commitments.csv`
  - normalized dated commitments used for audit/replay.

Generated by:

- `scripts/sync_opex_schedule.py`

## DB Sync Contract

- Target table: `fact_cashflow_commitments`
- OPEX rows are `commit_type='OPEX'`.
- Idempotency key: `(commit_date, commit_type, amount_kzt, scenario_tag, ref_id)`.
- Default mode: dry-run for DB writes.
- Apply mode requirements:
  - `ENABLE_CASHFLOW_WRITE=1`
  - `--apply`
- Optional replace:
  - `--replace-existing` deletes current `OPEX` commitments, then inserts normalized set.

## Operator Runbook

1. Dry-run parse and artifact refresh:
   - `python3 scripts/sync_opex_schedule.py --xlsx "<workbook_path>"`
2. Apply sync:
   - `ENABLE_CASHFLOW_WRITE=1 python3 scripts/sync_opex_schedule.py --xlsx "<workbook_path>" --apply --replace-existing`
3. Rebuild and export:
   - `ENABLE_CASHFLOW_WRITE=1 python3 scripts/rebuild_cashflow_calendar.py --apply`
   - `python3 scripts/update_cashflow_dashboard.py`
   - `python3 scripts/generate_business_insides.py --as-of YYYY-MM-DD`

## Validation Gates

- `python3 scripts/validate_params.py --strict`
- `python3 scripts/validate_on_delivery_freeze.py`
- `python3 scripts/validate_business_insides.py --as-of YYYY-MM-DD`

## Rollback

1. Restore DB backup:
   - `cp db/backups/app.db.pre_opex_business_insides_<timestamp>.sqlite db/app.db`
2. Re-run:
   - `python3 scripts/validate_params.py --strict`
   - `python3 scripts/update_cashflow_dashboard.py`
