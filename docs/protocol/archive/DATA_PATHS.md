# DATA_PATHS
## Purpose

Define canonical folders for the **Autonomous_business** repo so that
Project 3 (CRM/Python), Excel UI, and future tools all speak the same language
about where data lives.

Root assumption: repo lives at  
`~/Docs/Autonomous_business/`
db/ folder contains app.db (SQLite) and schema.sql.
All paths below are **relative to repo root**.

---

## 1. Core Data Folders

| Path                    | Purpose                                                                                 | Rules |
|-------------------------|-----------------------------------------------------------------------------------------|-------|
| `data_raw/`             | Raw exports from Kaspi / WB / suppliers (ActiveOrders, ArchiveOrders, stock dumps).    | Never edit in place; treat as read-only snapshots. |
| `data_stage/`           | Cleaned / normalized CSVs ready for DB ingest (e.g. parsed ActiveOrders, sales).       | Can be regenerated at any time from `data_raw/`. |
| `db/`                   | SQLite databases and migrations (`app.db`, migration scripts).                         | Only code writes here; no manual edits. |
| `exports/`              | Outgoing reports (replenishment plans, PO drafts, weekly reports, alerts).             | Safe to share / send. |
| `reports/`              | Analysis outputs (expansion scores, transfer recommendations, channel comparisons).    | Generated by analysis scripts. |
| `logs/`                 | Runtime logs from scripts and services.                                                 | Rotatable; can be truncated/archived. |
| `backups/`              | Zipped backups of databases and important exports.                                      | Never auto-deleted without a clear policy. |

Recommended key files:

- `docs/protocol/MIGRATION_LOG.md` — migration tracking (this file’s sibling).

- `docs/protocol/TASKS.yaml` — prioritized automation tasks.
- `config/paths.yaml` — additional machine-resolved paths if needed.

---

## 3. Principles

1. **Raw → Stage → DB → Exports**  
   - Every data flow should move in that direction. No script should write into `data_raw/`.

2. **Single source of truth per layer**  
   - Historical sales: DB (`fact_sales_raw`, `fact_sales_daily`), not random Excel files.
   - Inventory/ROP rules: `Master_Inventory_Rules_v5.3.md`.
   - Excel UI: `excel_ui/Inventory_Core_V15_FINAL.xlsx`.

3. **Relative paths only in code**  
   - Scripts should assume repo root and use relative paths (`data_raw/...`), not absolute `/Users/...`.

4. **Backups are sacred**
   - Only explicit "backup rotation" scripts are allowed to delete from `backups/`.

## 4. Channel-Specific File Paths (Phase 8)

### Kaspi Files

| File Pattern | Location | Purpose |
|--------------|----------|---------|
| `ActiveOrders_YYYY-MM-DD.xlsx` | `data_raw/` | Current active orders from Kaspi seller portal |
| `ArchiveOrders_*.xlsx` | `data_raw/` | Historical order exports |
| `Current_stock_YYYY-MM-DD.xlsx` | `excel/` | Daily inventory snapshot |

**Kaspi Expected Columns (Russian):**
- `Номер заказа` → order_id
- `Дата создания` → order_date
- `Артикул продавца` → kaspi_offer_name (contains sku_key + size)
- `Код товара` → sku_id
- `Количество` → quantity
- `Цена продажи` → sell_price_kzt

### Wildberries (WB) Files

| File Pattern | Location | Purpose |
|--------------|----------|---------|
| `WB_Sales_YYYY-MM-DD.xlsx` | `data_raw/` | WB sales report (weekly export) |
| `WB_Inventory_YYYY-MM-DD.xlsx` | `data_raw/` | WB FBO stock levels |
| `WB_Returns_YYYY-MM-DD.xlsx` | `data_raw/` | WB returns report |

**WB Expected Columns (Russian):**
- `Артикул продавца` → sku_key (e.g., "LINE52")
- `Дата продажи` → order_date
- `Цена розничная` → seller_price_rub
- `Кол-во` → quantity
- `Вайлдберриз реализовал` → net_revenue_rub
- `Склад` → warehouse_code

**WB Ingestion Command:**
```bash
python scripts/ingest_channel_sales.py data_raw/WB_Sales_2025-12-06.xlsx --channel WB
```

### Channel-Specific Exports

| File Pattern | Location | Purpose |
|--------------|----------|---------|
| `expansion_scores_YYYY-MM-DD.csv` | `reports/` | WB expansion scoring results |
| `transfer_recommendations_YYYY-MM-DD.csv` | `reports/` | Cross-channel transfer suggestions |
| `channel_comparison_YYYY-MM-DD.json` | `reports/` | SKU performance by channel |

## 5. WB Economics Reference

| Parameter | Value | Source |
|-----------|-------|--------|
| Commission | 24.5% | WB clothing category |
| Logistics | 408₽ | Per-unit proxy (actual varies by warehouse) |
| Tax | 3% | Kazakhstan tax on net revenue |
| FX Rate | 6.6 | RUB/KZT (update in `core/calc/wb_economics.py`) |

**Revenue Formula:**
```
WB Net Revenue (RUB) = Price × (1 - 24.5%) - 408₽
KZT Revenue = WB Net Revenue × 6.6 × (1 - 3%)
Profit = KZT Revenue - COGS
```
